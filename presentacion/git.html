git

Configuración inicial

Quiénes somos, con qué credenciales nos conectamos

Identidad


            git config --global user.name "Nombre Apellido"
            git config --global user.email "correo@ejemplo.com"
--global: aplica a todos los repos, no solo al actual. Es la identidad con la que quedan firmados los commits.

Clave SSH


            ssh-keygen -t ed25519 -C "correo@ejemplo.com"
-t ed25519: tipo de clave recomendado hoy (más corto y seguro que RSA). -C: solo una etiqueta para identificarla luego. Enter en todo genera id_ed25519 (privada, nunca se comparte) e id_ed25519.pub (pública, se sube a GitHub).

Registrar la clave


            Get-Content ~/.ssh/id_ed25519.pub | clip

GitHub → Settings → SSH and GPG keys → New SSH key


            ssh -T git@github.com
El último comando prueba la conexión: debe saludar con el usuario, no pedir contraseña ni dar error de permisos.

Clonar un repositorio


            git clone git@github.com:usuario/repositorio.git
Descarga una copia completa (todo el historial, todas las ramas). URL SSH porque ya tenemos la clave configurada.

Plan B: sin GitHub


            git init --bare curso-practica.git
            git clone curso-practica.git mi-copia
Sin acceso a GitHub, tampoco hay forma de montar un servidor para toda el aula: cada persona trabaja con un remoto local propio, en su misma máquina. No hay colaboración real con el grupo, pero la mecánica (clone/push/pull/merge) es idéntica, y no hace falta clave SSH al no haber autenticación de por medio.

Crear una rama


          git checkout -b mi-rama
Crea y cambia a la rama en un solo comando. Nuestros cambios no afectan a main hasta que hagamos merge: podemos equivocarnos sin riesgo para el resto. "git branch" lista ramas existentes; "git checkout rama" cambia sin crear.

Ciclo básico


            git status
El comando que se ejecuta constantemente: rama actual, ficheros cambiados, qué está ya preparado para commit. 

            git add <fichero>
Prepara el fichero para el próximo commit. "git add ." lo prepara todo de golpe. 

            git commit -m "mensaje descriptivo"
El mensaje explica el porqué, no el qué — el qué ya se ve en el diff. 

            git push -u origin mi-rama
-u vincula la rama local con la remota; a partir de ahí basta "git push" a secas. 

            git pull
Descarga e integra cambios del remoto. Hacerlo al empezar a trabajar, para no acumular demasiada diferencia con el resto del equipo.

Merge


          git merge main
Integra en la rama actual los commits de otra rama. Para poner al día una rama de trabajo, o para integrar una rama acabada de vuelta en main. Si dos ramas tocan lo mismo de forma incompatible: conflicto (siguiente bloque).
