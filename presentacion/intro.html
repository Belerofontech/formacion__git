Presentación libre. Dejar claro que las dudas se pueden preguntar durante el día, no solo al final — el correo es para después del curso.

Objetivo

Descubrir y aprender las bases de diferentes metodologías de trabajo, para encontrar un equilibrio entre eficiencia a la hora de trabajar y robustez del código.

Esto no es un curso de Python desde cero, es de hábitos de desarrollo — salir con cosas aplicables directamente en el día a día.

Qué NO es objetivo

Aprender de memoria comandos o sintaxis específica, recursos, librerías, etc.

Lo importante es el criterio de cuándo y por qué aplicar cada práctica, no memorizar la sintaxis exacta — eso siempre se puede buscar.

Cómo conseguís el material

Plan A: git clone del repositorio del curso

Es, de hecho, vuestro primer contacto con git del día, antes incluso de llegar al bloque de git.

Plan B: sin acceso a GitHub

Os paso el material de otra forma (USB / carpeta compartida)

Si no hay GitHub, el material llega igual, solo que sin git de por medio. Git en sí lo practicamos más tarde con el plan B de esa sección (remoto local).

Contexto de trabajo

Hoy trabajamos con scripts (.py), no con Jupyter notebooks

¿Por qué?

Por qué: un notebook no versiona bien en git (los diffs de las celdas de salida son ilegibles), no se testea bien con pytest, y breakpoint()/pdb no funciona igual de bien ahí. Todo lo que vemos hoy encaja mejor en un .py normal.
